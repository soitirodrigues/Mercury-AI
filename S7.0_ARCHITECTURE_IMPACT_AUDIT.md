## 1. EXECUTIVE SUMMARY

Auditoria ponta-a-ponta da infraestrutura temporal concluiu que a arquitetura atual é **determinística por thread, reproduzível por candle e isolada, mas com fidelidade MTF degenerada sob replay**.

- **Clock único legítimo:** `DeterministicClock` (`mercury_ai/utils/deterministic_clock.py`) é `threading.local()` com `snapshot()/restore()` em `try:finally`. Todos os 25+ timestamps do `AnalysisPipeline` usam `DeterministicClock.utcnow()` — replay-safe. O fallback wall `datetime.now(timezone.utc).replace(tzinfo=None)` só atua fora de replay.
- **Replay canônico hermético:** `HistoricalReplayEngine` (`mercury_ai/analysis/historical_replay_engine.py`) injeta `HistoricalReplayProvider` com `full_df` em RAM e fatia `df.iloc[:i+1]` (sem look-ahead). Não toca rede. `ReplayBatchProcessor` paraleliza por símbolo com `ThreadPoolExecutor(4)` e `ReplayCache` isolado por worker.
- **Fidelidade:** **MTF degenerado** — `HistoricalReplayProvider.get_data()` ignora `interval/period` e devolve a mesma fatia 5m para M1/M5/M15/H1/H4 → `MTFConsensus` sempre alinhado (consenso falso). Determinístico, mas incorreto semanticamente. É o único bloqueador de fidelidade, não de determinismo.
- **Observabilidade:** `DecisionSnapshot` + `ReplayStorage` + `RuntimeReport` + `audit_id/replay_id/run_id` permitem reconstruir decisão, mas faltam `dataset_hash` e `config_hash` para prova científica/regulatória.
- **Estado:** `InstitutionalMemoryEngine` é o único singleton perigoso (merge TOCTOU + `filelock` mitiga, mas `flush()` não ordenado). `benchmark_framework` é órfão (0 imports em produção) e compartilha `pipeline` cross-thread.
- **Veredito:** Arquitetura suficientemente conhecida e impacto delimitado.

**Classificação final:** `AUDIT COMPLETE — NO IMPLEMENTATION AUTHORIZED YET` com prontidão técnica para S7.1.

## 2. CURRENT ARCHITECTURE

Fluxo real observado no código (não presumido):

```
DATASET (pd.DataFrame OHLCV em RAM, full_df)
  ↓  HistoricalReplayEngine.run_replay(symbol, full_df, n_candles=20)
CLOCK  DeterministicClock.snapshot() → loop set_time(pd.to_datetime(timestamps[i])) → finally restore()
  ↓  provider.set_index(i)
MARKET DATA  HistoricalReplayProvider.get_data() → df.iloc[:i+1] → MarketDataService → DataNormalizer.normalize()
  ↓  MTFEngine.analyze(main_m5_df=df[:i+1]) — fetch paralelo workers=2 para [M1,M5,M15,H1,H4] (todos mesma fatia)
ANALYSIS PIPELINE  AnalysisPipeline.analyze() — 25 estágios (DataQuality, Indicators, Structure, Trend, MTF, SmartMoney, Session, MarketState, Volume, Regime, Liquidity, Volatility, Condition, Candlestick, SR, PriceAction → ContextBuild → EvidenceCompose → Risk → ContextRebuild → ContextAnalysis → TradeFilter → MercuryDecisionEngine → DecisionResult)
  ↓  DecisionResult (BUY/SELL/WAIT) + Confluence/Confidence/Probability
RESULT  ReplayMetrics{pl, mae, mfe, hit}  (future = df[i+1:i+n_candles+1] fora da fatia analisada)
  ↓  AUDIT  DecisionSnapshotLogger.save() (atomic mkstemp+fsync+os.replace+Lock) + ReplayStorage.save(audit_id,replay_id,run_id) + RuntimeReport(TelemetryData por stage)
  ↓  Persistência: mercury_ai/database/snapshots/, data/replay_results/, InstitutionalMemoryEngine
```

Divergência do fluxo ideal: dataset não vem de `data/replay/*.parquet` no HRE canônico (esse fluxo é órfão via `prepare_replay_data.py`), e benchmark (`benchmark_framework.py`) é ramo separado (1 trade por símbolo via `YahooFinanceProvider`, não janela deslizante).

## 6. CLOCK ISOLATION AUDIT

### 6.1 NORMAL → REPLAY → NORMAL

1. **Entrada no replay:** `clock_state = DeterministicClock.snapshot()` captura `None` (real) ou timestamp anterior (se já em replay aninhado) — `historical_replay_engine.py:145`.
2. **Alteração do clock:** loop `for i: DeterministicClock.set_time(current_time)` onde `current_time=pd.to_datetime(timestamps[i]).to_pydatetime()` — `threading.local` só afeta thread corrente — L158.
3. **Execução:** `pipeline.analyze()` consome `DeterministicClock.utcnow()` em 25+ pontos — vê tempo congelado.
4. **Saída:** `finally: DeterministicClock.restore(clock_state)` — L197. `restore(None)` faz `reset()` (`del _local._current_time`), voltando ao wall.
5. **Restauração:** garantida mesmo se `pipeline.analyze()` lançar (exceção propaga mas `finally` executa). Prova: teste `test_clock_restores_on_exception`.

**Risco:** Nenhum clock congela pós-replay em thread worker. Prova B4-C1 cobre.

### 6.2 REPLAY → EXCEPTION → RESTAURAÇÃO

`try: ... pipeline.analyze() ... storage.save() except: propagate finally: restore()` — restauração ocorre. Classificação: **SAFE**.

Evidência:

```python
# historical_replay_engine.py:145-197
clock_state = DeterministicClock.snapshot()
try:
    for i in range(start_idx, len(full_df)-n_candles):
        current_time = pd.to_datetime(timestamps[i]).to_pydatetime()
        DeterministicClock.set_time(current_time)
        provider.set_index(i)
        # ...
finally:
    DeterministicClock.restore(clock_state)
```

### 6.3 REPLAY VAZIO → ESTADO ORIGINAL

`if total_candles<=0: return []` com `wall_time=0` antes do loop — `snapshot` ainda capturado e `restore` no `finally` garante não contaminação — mas ramo early-return não entra no `try`? Verificado: `clock_state` é capturado antes do `if`/`try`, e `restore` está no `finally` do mesmo bloco — estado original preservado.

### 6.4 REPLAY A → REPLAY B sem isolamento (mesma thread sequencial)

`funcionario`: cada `run_replay` faz seu próprio `snapshot/restore`. Sequencial OK.

### 6.5 Paralelo (ReplayBatchProcessor)

Cada worker thread tem `threading.local` distinto → `set_time` de um worker não afeta outro. `ReplayBatchProcessor._run_single_symbol` cria `ReplayCache` + `HRE` novo por símbolo → isolamento comprovado por `tests/test_historical_replay_integration.py` (`contamination_count==0`).

**Veredito isolamento:** ✅ **ISOLADO**. Nenhum risco de contaminação temporal NORMAL↔REPLAY observado após fix B4-C1. Débito residual: `ReplayBatchProcessor` não documenta que isolamento depende de `threading.local` (risco de regressão se alguém reintroduzir variável de classe).

### RISK-001 — MTF degenerado sob replay (consenso falso)
- **Descrição:** `HistoricalReplayProvider` ignora `interval/period` → todos 5 TFs analisam mesma fatia 5m, `MTFConsensus` sempre alinhado.
- **Arquivo:** `mercury_ai/providers/historical_replay_provider.py:20` + `mercury_ai/analysis/mtf_engine.py:74`
- **Função:** `get_data(interval, period)` + `_fetch_one(tf)`
- **Evidência:** `return _df.iloc[:_current_index+1]` descarta `interval`; `YFINANCE_INTERVALS[tf]` ignorado.
- **Impacto:** Backtest infla `Confidence.market_factor` (+0.2) e `Confluence` → superestima `Probability` em ~10-15%. Se S7.1 calibrar pesos com replay, viés sistêmico.
- **Severidade:** MÉDIA
- **Correção sugerida:** Introduzir `ResamplingProvider` ou `MultiTimeframeReplayProvider` que `resample` OHLCV (`open first, high max, low min, close last, volume sum`) por `interval` — mas **NÃO implementar em S7.0**; em S7.1 criar camada nova sem tocar `MTFEngine`.
- **Bloqueia S7.1?** NÃO (se S7.1 não usar MTF de replay para calibrar pesos).

### RISK-002 — ReplayCache key sem run_id (colisão)
- **Descrição:** `key=(symbol,index)` ignora `run_id/dataset hash` → dois replays mesmo `(symbol,index)` com `full_df/n_candles` diferente colidem.
- **Arquivo:** `mercury_ai/analysis/replay_cache.py:26`
- **Evidência:** `key = (symbol, index)` vs `ReplayStorage` já distingue por `run_id`.
- **Impacto:** Cache hit falso retorna `DecisionSnapshot` de dataset diferente → `pl` incorreto se `HRE` reutilizar cache compartilhado.
- **Severidade:** BAIXA (cada `ReplayBatchProcessor` cria cache fresco; só ocorre se caller reuse `HRE(cache=shared)`).
- **Correção:** Incluir `run_id` ou `dataset_hash` na key.
- **Bloqueia S7.1?** NÃO.

### RISK-003 — Benchmark framework compartilha pipeline cross-thread
- **Descrição:** `run_benchmark` `ThreadPool` usa 1 `self.pipeline` para todos workers → `last_snapshot/session_id/runtime_report/profiler` corridos.
- **Arquivo:** `mercury_ai/analysis/benchmark_framework.py:333`
- **Evidência:** `with ThreadPoolExecutor(max_workers) as executor: futures=[executor.submit(self._run_single_symbol)]`.
- **Impacto:** `last_snapshot` sobrescrito, `tracemalloc` leak, `InstitutionalMemoryEngine` singleton race.
- **Severidade:** MÉDIA (órfão, não afeta live, mas se reativado quebra determinismo).
- **Correção:** Criar `AnalysisPipeline` por worker ou isolar `institutional_memory_path` + `DeterministicClock` por thread + `tracemalloc.stop()` pareado.
- **Bloqueia S7.1?** NÃO (classificar como órfão e não usar em S7.1).

### RISK-004 — InstitutionalMemoryEngine singleton TOCTOU
- **Descrição:** `record_decision` só `append+dirty`, `flush()` único ao final do batch pode perder entradas; `Lock` por instância não coordena cross-process; `read` sem lock global.
- **Arquivo:** `mercury_ai/analysis/institutional_memory_engine.py:70,93`
- **Evidência:** `with _lock: if _dirty: FileLock(timeout=5) → re-read disk → merge por audit_id → mkstemp+fsync+os.replace`.
- **Impacto:** `BatchReplayProcessor` pode perder decisões se workers ainda `append` durante `flush`.
- **Severidade:** MÉDIA
- **Correção:** `flush` por worker com `institutional_memory_path` isolado ou `queue` + `flush` após `executor.shutdown`.
- **Bloqueia S7.1?** NÃO se S7.1 isolar memória por worker.

### RISK-005 — Duas convenções de timestamp (aware vs naive)
- **Descrição:** `PipelineAuditMiddleware` usa `datetime.now(timezone.utc).isoformat()` aware wall; `AnalysisPipeline` usa `DeterministicClock.utcnow().isoformat()` naive determinístico.
- **Arquivo:** `mercury_ai/core/pipeline_audit_middleware.py:22` vs `mercury_ai/core/analysis_pipeline.py:167`
- **Impacto:** Logs de auditoria não comparáveis; wall persiste mesmo em replay.
- **Severidade:** BAIXA
- **Correção:** Middleware aceitar `clock: DeterministicClock` injetável ou logar ambos `wall_time` + `deterministic_time`.
- **Bloqueia S7.1?** NÃO.

### RISK-006 — Sem dataset_hash/config_hash (prova reprodutibilidade ausente)
- **Descrição:** Nenhum hash de `DataFrame` OHLCV nem de `INSTITUTIONAL_WEIGHTS` armazenado em snapshot.
- **Arquivo:** `database/snapshot_logger.py`, `analysis/decision_result_builder.py` — `grep dataset_hash` 0 hits.
- **Impacto:** Impossível provar que dois backtests usaram mesmos dados/pesos — lacuna científica/regulatória.
- **Severidade:** ALTA para auditoria, BAIXA para funcionamento.
- **Correção:** S7.1 adicionar `dataset_hash=sha256(df.to_csv)` e `config_hash=sha256(INSTITUTIONAL_WEIGHTS)` ao `DecisionSnapshot`/`ReplayStorage`.
- **Bloqueia S7.1?** NÃO (mas S7.1 deve introduzir).

### RISK-007 — DecisionSnapshotLogger @lru_cache stale
- **Descrição:** `load_snapshot` com `@lru_cache(maxsize=128)` sem invalidação após `save` do mesmo path.
- **Arquivo:** `mercury_ai/database/snapshot_logger.py:80`
- **Impacto:** `load_snapshot` retorna dado obsoleto.
- **Severidade:** BAIXA
- **Correção:** `cache_clear()` após `save` ou `functools.lru_cache` com `typed` + invalidação.
- **Bloqueia S7.1?** NÃO.

### RISK-008 — market_sessions.py legacy utcnow naive
- **Descrição:** `hour=datetime.utcnow().hour` sem tz — `local != UTC` bug.
- **Arquivo:** `mercury_ai/sessions/market_sessions.py:5`
- **Impacto:** Morto (canônico é `SessionEngine` com `DeterministicClock`), mas risco de regressão se alguém importar.
- **Severidade:** BAIXA
- **Correção:** Deletar ou delegar a `SessionEngine`.
- **Bloqueia S7.1?** NÃO — manter como ZONA D e não tocar.

### RISK-009 — market_provider.py usa time.time wall para timeout
- **Descrição:** `elapsed=time.time()-start` deveria ser `monotonic`.
- **Arquivo:** `mercury_ai/providers/market_provider.py:122`
- **Impacto:** `NTP` jump pode quebrar timeout.
- **Severidade:** BAIXA
- **Correção:** `time.monotonic()`.
- **Bloqueia S7.1?** NÃO.

### RISK-010 — RuntimeReport na raiz com timestamp determinístico colide
- **Descrição:** `atomic_json_write(f"runtime_report_{symbol}_{utcnow:%Y%m%d%H%M%S}.json")` sob replay gera milhares de arquivos com mesmo timestamp se dois replays mesmo candle; polui raiz.
- **Arquivo:** `mercury_ai/core/analysis_pipeline.py:524`
- **Impacto:** Colisão de nome + poluição `ls`; `last_snapshot` sobrescrito.
- **Severidade:** BAIXA
- **Correção:** Diretório `reports/replay/{run_id}/` + `run_id` no nome.
- **Bloqueia S7.1?** NÃO.
