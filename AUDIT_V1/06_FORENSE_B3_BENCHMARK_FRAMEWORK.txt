4. REPRODUÇÃO DO ACHADO ORIGINAL
--------------------------------------------------------------------------------
Probe pré-correção (_probe_b3.py), chamando a fórmula exata do caminho default
de _run_single_symbol / run_quick_benchmark:

    if decision == "BUY":  outcome = score * 0.02
    elif decision == "SELL": outcome = -score * 0.02
    else: outcome = 0.0

PROBE A — direcional perfeito (acerta 100% dos BUY/SELL):
    - Todo BUY tem outcome > 0 e todo SELL tem outcome < 0 POR CONSTRUÇÃO.
    - accuracy = (tp+tn)/total = 1.0 SEMPRE (resultado independente do mercado).
PROBE B — preditor bom (sinais alinhados ao mercado) vs preditor INVERSO:
    - Com outcomes REAIS de mercado: bom => accuracy 1.0; inverso => accuracy 0.0.
    - Com o caminho sintético default (score*0.02): AMBOS => accuracy 1.0.
      => O framework NÃO consegue distinguir um preditor bom de um inverso
         (evidência definitiva de auto-validação).
PROBE C — caminho real de código:
    - _run_single_symbol (default) produz outcome == score*0.02 bit-a-bit,
      sem consultar mercado (outcome calculado apenas de result.decision).

--------------------------------------------------------------------------------
5. RESULTADO DA REPRODUÇÃO
--------------------------------------------------------------------------------
CONFIRMADO: exit 0 em todos os probes. A circularidade é real e reproduzível:
  - accuracy = 1.0 trivial para qualquer modelo direcional (não depende do mercado);
  - modelo "cego" 100% BUY => profit_factor = inf (nunca há perda possível);
  - preditor bom e preditor inverso são INDISTINGUÍVEIS pelas métricas no caminho
    default;
  - o outcome é uma função determinística do PRÓPRIO score do modelo.

Detalhe documentado (nuance): profit_factor=inf só ocorre quando o modelo é 100%
BUY (sem outcomes SELL, logo sem perdas). A accuracy=1.0 vale para qualquer
modelo direcional (BUY/SELL), pois outcome tem o sinal do próprio decision.

8. TESTE DE AUTO-VALIDAÇÃO
--------------------------------------------------------------------------------
Cenários aplicados (mapeamento do sprint):
  A. baseline antigo + execução atual          -> outcome sintético (score*0.02)
  B. baseline igual ao resultado atual         -> outcome == score*0.02 (bit-a-bit)
  C. baseline artificialmente "melhor"         -> irrelevante: outcome não é do mercado
  D. baseline artificialmente "pior"           -> irrelevante: outcome não é do mercado
Esperado (sprint): baseline atual NÃO pode tornar a execução automaticamente
aprovada. OBSERVADO: no caminho default, TODOS os cenários dão accuracy=1.0 e
métricas financeiras derivadas do próprio score => a execução se auto-aprova.
FALHA do requisito de independência => auto-validação confirmada (B3-D).

9. ANÁLISE TEMPORAL
--------------------------------------------------------------------------------
_get_real_outcome (caminho de "outcome real"):
  - provider = YahooFinanceProvider(); df = provider.get_data(symbol);
  - raw_return = (close[-1] - close[-2]) / close[-2]  (retorno do ÚLTIMO candle)
  - NÃO é forward-looking (usa as duas últimas velas da série, não a próxima).
  - Em falha: retorna 0.0 (neutro) com logger.warning.
Nota: mesmo no caminho "real", o retorno é do último candle da janela baixada
(parcialmente look-ahead em relação ao instante da decisão se a janela incluir
a vela em que a decisão foi tomada). Registrado como risco residual (item 24),
não corrigido (fora do escopo mínimo B3).

10. ANÁLISE DE UNIDADES
--------------------------------------------------------------------------------
CRÍTICO (B3-G): escala do score.
  - confidence_engine.py linha 84: score = 100.0 * (...)  => ESCALA 0-100.
  - mocks de teste usam score = 85.0 (escala 0-100).
  - benchmark_framework usa outcome = score * 0.02 com a intenção de "~2% max".
    Com score 0-100: outcome varia de 0 a 200% ("retornos" inflados 100x).
    Ex.: score=80 => outcome = +1.6 = +160% em UM trade (absurdo financeiro).
  - O comentário do código supõe escala 0-1 (implícito em "~2% max").
Inconsistência de contrato de unidade: fabricação usava escala errada, além de
ser circular. A correção B3 elimina a fabricação inteira (não apenas a escala).
