## Report 20 - Sprint A: Data Quality Gate Gap-Aware Validation

### Executive Summary
This report documents the complete Sprint A — Data Quality Gate / Gap-Aware Validation for Mercury AI V1. The sprint addresses a CRITICAL blocker where the E2E main.py produced exit 0 with 0 decisions because the Data Quality Gate rejected all assets with "Temporal gaps detected (Score: 0.4)".

### Primary Objective
Make the Data Quality Gate distinguish between real data gaps and legitimate market closures/artifacts, specifically the Yahoo Finance crypto 45min gap at UTC midnight.

### Background / Problem Statement
- **E2E Failure**: `python -m mercury_ai.main` produced exit 0 with 0 decisions
- **Root Cause**: Data Quality Gate rejected ALL assets with score 0.4 due to temporal gaps
- **Specific Issue**: Yahoo Finance crypto data has a 45-minute gap at UTC midnight (legitimate market closure artifact, NOT unexpected data loss)
- **Impact**: All assets were rejected, producing no trading decisions

### Technical Details

#### Gap Classification Logic
```python
# Gaps > 3x interval: check if crosses UTC day boundary
if gap > 3 * expected_interval:
    if crosses_utc_day_boundary(timestamps):
        # Expected non-trading period (e.g., Yahoo Finance crypto midnight gap)
        score = 0.8  # Minimal degradation
        status = "PASS"
    else:
        # Unexpected data gap
        score = 0.4  # Rejection threshold
        status = "FAIL"
else:
    # Normal gap within expected range
    status = "PASS"
```

#### Expected Intervals
- Computed from median time_diffs of the asset's dataset
- Used as reference for gap classification threshold (3x)

#### Gap Size Categories
- **< 2x interval**: NORMAL → PASS
- **2-3x interval**: MINOR_SKIP → PASS with minor score reduction
- **> 3x interval**: Requires day-boundary check
  - Crosses UTC day → `EXPECTED_NON_TRADING` → PASS (score 0.8)
  - Does not cross UTC day → `UNEXPECTED_DATA_GAP` → FAIL (score 0.4)

#### NaT (Not-a-TimeStamp) Handling
- Explicitly detected and rejected
- Any NaT in timestamp series → automatic FAIL
- Prevents silent failures from malformed timestamps
