5. CAUSA R1
================================================================================
- Função: mercury_ai/database/snapshot_logger.py::_sanitize_filename_component.
- Whitelist: _SAFE_SYMBOL_RE = re.compile(r"^[A-Za-z0-9._\-]+$") — NÃO inclui '+'.
- save() chama _sanitize_filename_component(str(snapshot.timestamp)) para
  montar {asset}_{timestamp}.json.
- snapshot.timestamp é string (DecisionSnapshot.timestamp: str), produzida por
  DeterministicClock.utcnow().isoformat(). Em tempo real é naive (sem offset);
  em replay com dataset tz-aware (ex.: parquet Europe/London) é aware e o
  isoformat contém '+01:00'.
- O '+' do offset ISO 8601 NÃO passa no whitelist -> ValueError.
- Por que um timestamp aware válido provoca falha: o whitelist foi projetado
  para path-traversal (chars de arquivo), mas não previu o sinal de offset ISO
  8601. A validação é de SEGURANÇA (não de formato de timestamp); '+'
  é inofensivo em filename, mas o regex o rejeita.
- NÃO corrigido ainda nesta seção (identificação apenas).

6. CONTRATO DE SNAPSHOT
================================================================================
Representação atual determinada pelo código:
- Timestamp salvo = str(snapshot.timestamp) = string ISO 8601
  (DeterministicClock.utcnow().isoformat()).
- O JSON preserva o string ORIGINAL EXATO via json.dumps(asdict(snapshot),
  default=str) — o instante NÃO é alterado pela serialização.
- O FILENAME é apenas identificador filesystem-safe; nenhum consumidor parseia
  o filename para obter o instante (todos leem data['timestamp'] do JSON:
  performance_analytics, institutional_analytics_engine, app pages, etc.).
Comparação semântica:
  - aware UTC      (2024-01-01T07:40:00+00:00) = mesmo instante do naive 07:40
  - aware local    (2024-01-01T07:40:00+01:00) = 06:40 UTC
  - naive UTC      (2024-01-01T07:40:00)       = contrato do tempo real
Requisito: o timestamp salvo deve representar o MESMO INSTANTE. Não alterar
arbitrariamente para horário local; não remover offset alterando o instante.
ESCOLHA: o JSON mantém a string original (instante preservado); o filename
precisa apenas ser filesystem-safe. Correção compatível com o contrato
existente e com os consumidores.

  REMOVE o trade do agrupamento mensal/semanal; _overview_stats date_range
  ignora NaT; sort_values coloca NaT no fim. Em cenário misto (real-time naive
  + replay aware no mesmo snapshot_dir), TODOS os snapshots aware seriam
  excluídos da análise.
- NÃO remover errors="coerce" automaticamente; manter para inválidos.
