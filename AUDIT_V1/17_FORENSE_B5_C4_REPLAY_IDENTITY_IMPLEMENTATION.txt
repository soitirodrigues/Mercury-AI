3. Implementação de replay_id
--------------------------------------------------------------------------------

3.1 Cálculo do hash (snapshot_logger.py)

Função: compute_replay_id_from_snapshot(snapshot)
Localização: mercury_ai/database/snapshot_logger.py, ~linha 45

Implementação:

    def compute_replay_id_from_snapshot(snapshot):
        replay_input = (
            f"{snapshot.asset}|"
            f"{snapshot.timeframe}|"
            f"{snapshot.timestamp}|"
            f"{snapshot.session_id}|"
            f"{snapshot.decision_result.audit_id}"
        )
        return hashlib.sha256(replay_input.encode()).hexdigest()

Componentes do hash:
  - asset          : identificador do ativo (ex: "BTCUSDT")
  - timeframe      : granularidade temporal (ex: "1h")
  - timestamp      : timestamp ISO-8601 da decisão
  - session_id     : identificador de sessão de análise
  - audit_id       : SHA-256 do snapshot de evidências (definido em B5-C3)

Resultado: string hexadecimal de 64 caracteres (SHA-256).

Propriedade: DETERMINÍSTICO — mesmas entradas produzem sempre o mesmo
replay_id, garantindo reprodutibilidade跨 execuções.

3.2 Sanitização de nomes de arquivo (snapshot_logger.py)

Função: _sanitize_filename_component(value)

    def _sanitize_filename_component(value):
        # Rejeita path traversal
        if ".." in value or "/" in value or "\\" in value:
            raise ValueError(f"unsafe filename component: {value}")
        result = value.replace(":", "-").replace("=", "_").replace("+", "_")
        if not re.match(r"^[A-Za-z0-9._\-]+$", result):
            raise ValueError(f"unsafe filename component after sanitize: {result}")
        return result

Substituições:
  ":"  → "-"   (timestamps ISO-8601)
  "="  → "_"   (separadores de query)
  "+"  → "_"   (encoding de URL)

Validação final: regex ^[A-Za-z0-9._\-]+$ — rejeita qualquer caractere
fora do conjunto seguro para sistemas de arquivos.

3.3 Consistência no DecisionSnapshotLogger.save (snapshot_logger.py)

    replay_id = compute_replay_id_from_snapshot(snapshot)
    if snapshot.replay_id and snapshot.replay_id != replay_id:
        raise ValueError(
            f"replay_id mismatch: snapshot={snapshot.replay_id} "
            f"computed={replay_id}"
        )
    data["replay_id"] = replay_id

Garante que, se um replay_id pré-computado existir no snapshot, ele deve
ser idêntico ao hash recalculado. Qualquer divergência é um erro fatal.


4. Implementação de run_id
--------------------------------------------------------------------------------

4.1 Parâmetro opcional em ReplayStorage.save (replay_storage.py)

Assinatura:

    def save(
        self,
        audit_id: str,
        snapshot,
        metrics: ReplayMetrics,
        run_id: str = ""
    ) -> str:

run_id é um parâmetro OPCIONAL (default ""). Quando vazio, o arquivo de
saída não recebe sufixo de execução. Quando fornecido, é sanitizado e
anexado ao nome do arquivo.

4.2 Sanitização de run_id (replay_storage.py)

    safe_run_id = _sanitize_audit_id(run_id) if run_id else ""

A função _sanitize_audit_id reaproveita a mesma lógica de
_sanitize_filename_component: substitui ":" → "-", rejeita path traversal
("..", "/", "\"), valida contra ^[A-Za-z0-9._\-]+$.

4.3 Construção do nome de arquivo (replay_storage.py)

    replay_id = compute_replay_id_from_snapshot(snapshot)
    safe_audit_id = _sanitize_audit_id(audit_id)
    safe_run_id = _sanitize_audit_id(run_id) if run_id else ""
    run_suffix = f"_{safe_run_id}" if safe_run_id else ""
    filepath = f"{self.output_dir}/{safe_audit_id}_{replay_id}{run_suffix}.json"

Exemplos de nomes de arquivo gerados:

  Sem run_id:
    data/replay_results/{audit_id}_{replay_id}.json

  Com run_id="run_42":
    data/replay_results/{audit_id}_{replay_id}_run_42.json

4.4 Persistência de run_id no JSON (replay_storage.py)

O dicionário de dados gravado inclui o campo run_id:

Isso garante que run_id é recuperável tanto do nome do arquivo quanto do

5. Detecção de Duplicatas
--------------------------------------------------------------------------------

5.1 Mecanismo (_existing_file_matches em replay_storage.py)

Após construir o filepath, ReplayStorage.save verifica se já existe um
arquivo correspondente:

    existing = glob.glob(
        os.path.join(self.output_dir, f"{safe_audit_id}_{replay_id}*.json")
    )

Para cada arquivo encontrado, carrega o JSON e compara campo a campo com
os novos dados.

5.2 Política de duplicatas

  (a) Conteúdo idêntico (todos os campos coincidem):
      → SKIP (log info: "duplicate replay identity, content matches — skipping")
      → Não reescreve o arquivo. Idempotência garantida.

  (b) Conteúdo divergente (mesmo replay_id + run_id, dados diferentes):
      → raise ValueError(
            "duplicate replay identity detected for "
            f"replay_id={replay_id} run_id={safe_run_id} "
            f"audit_id={safe_audit_id}"
        )
      → Sinaliza corrupção ou não-determinismo: duas execuções com a mesma
        identidade produziram resultados diferentes.

5.3 Thread-safety e atomicidade

  - threading.Lock protege toda a operação de save.
  - Escrita atômica via tempfile + os.replace (atomic_json_write).
  - Nenhum arquivo parcial é visível durante a escrita.

7. Bug Fixes Colaterais
--------------------------------------------------------------------------------

7.1 cache_misses_before em historical_replay_engine.py

BUG (relatado em AUDIT_V1 Part 1):
  O código usava self._cache.stats.get("misses_before", 0) — chave
  "misses_before" NUNCA existia no dicionário de stats, retornando
  sempre 0. Consequentemente, cache_total era sempre calculado como
  cache_hits + (misses_atuais - 0) = cache_hits + misses_atuais, que
  inclui misses de execuções anteriores, inflando cache_total.

FIX (linhas 138-139, 200-201):

    cache_hits_before = self._cache.stats["hits"]
    cache_misses_before = self._cache.stats["misses"]
    ...
    cache_hits = self._cache.stats["hits"] - cache_hits_before
    cache_total = cache_hits + (self._cache.stats["misses"] - cache_misses_before)

Agora captura o valor real de misses ANTES da execução e subtrai após,
garantindo que cache_total reflete apenas os misses DESTE replay.

7.2 MarketClosedException em confidence_calibration_auditor.py

BUG:
  YahooFinanceProvider._validate_schema levanta MarketClosedException
  quando há menos de 20 barras de dados (mercado fechado/fim de semana).
  O except clause do ConfidenceCalibrationAuditor não capturava essa
  exceção, causando crash em testes que simulam mercado fechado.

FIX (linhas 7, 34):

    from mercury_ai.core.exceptions import MarketClosedException
    ...
    except (KeyError, IndexError, ValueError, ConnectionError,
            RuntimeError, MarketClosedException):
        continue

Agora o auditor lida graciosamente com dados insuficientes, fazendo
skip da iteração em vez de propagar a exceção.

10. Contrato de Identidade Implementado
--------------------------------------------------------------------------------

  Identidade       | Campo JSON    | Origem           | Determinístico
  -----------------+---------------+------------------+---------------
  audit_id         | audit_id      | SHA-256 evidences| Sim (B5-C3)
  replay_id        | replay_id     | SHA-256 snapshot  | Sim (B5-C4)
  session_id       | session_id    | Runtime UUID     | Não
  run_id           | run_id        | Caller-supplied  | Não (opcional)

Hierarquia de identidade:

  replay_id = SHA-256(asset | timeframe | timestamp | session_id | audit_id)
  audit_id  = SHA-256(asset | timeframe | timestamp | len(evidences) | evidence_hash)

replay_id é uma SUPER-IDENTIDADE que incorpora audit_id como componente.
Dois snapshots com o mesmo replay_id são, por construção, idênticos em
todos os campos que determinam a decisão. Se o conteúdo persistido
divergir, isso indica não-determinismo ou corrupção — daí a rejeição.
